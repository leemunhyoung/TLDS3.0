# 폴드폰 대응 기준

버전: v0.1 · 기준일: 2026-11-04 · 사용자 합의 반영

## 목적과 범위

더 라운지 3.0은 반응형 기반 고도화 프로젝트다. 폴드 대응은 기존 데이터·기능·정보 구조를 유지하면서 배치와 레이아웃을 조정하는 범위로 제한한다. 신규 백엔드 데이터·API·서비스 기능을 전제로 설계하지 않는다.

적용 예상 페이지는 제휴카드 페이지·마이페이지·사용처 페이지다. 현재는 예상 범위이며, 구체적인 적용 화면과 노드는 실제 설계 검토 후 확정한다. 그 외 페이지는 현재 APP 및 기존 반응형 기준을 적용하며, 폴드 전용 시안을 일괄 추가하지 않는다.

| 대상 | 펼친 상태의 확장 배치 | 접힌 상태 |
|---|---|---|
| 마이페이지 | 기존 정보 영역을 넓어진 공간에 맞게 재배치. 구체적인 영역 구성은 실제 APP 설계 기준으로 정의 | 현재 작업 중인 APP 레이아웃 |
| 사용처 페이지 | 좌측 2뎁스 카테고리 탐색 + 우측 선택한 카테고리의 기존 콘텐츠 | 현재 APP 탐색 방식과 레이아웃 |
| 제휴카드 페이지 | 좌측 등록 카드 썸네일 선택 + 우측 선택 카드의 이용 가능한 이용권 목록·혜택 | 현재 APP의 해당 카드·콘텐츠 화면 |

접힌 화면에는 실제 가용 너비에 맞춘 기존 반응형 규칙을 적용한다. 375px는 현재 APP 대표 시안 크기이며 모든 접힌 화면의 고정 너비를 뜻하지 않는다. 펼친 상태에서도 확장 배치를 적용할 충분한 공간이 있어야 한다.

## 사용처 페이지

- 좌측 대카테고리: 라운지·다이닝·공항커피·공항골프 등 기존 설계서 항목을 사용한다.
- 라운지 하위에는 국내라운지·전세계라운지·럭셔리라운지를 표시할 수 있도록 2뎁스 펼침을 고려한다.
- 하위 항목의 들여쓰기·긴 이름·메뉴 전체 길이를 수용하는 좌측 영역을 설계한다.
- 메뉴의 펼침 상태와 실제 선택 상태를 구분한다. 우측에는 선택한 항목의 기존 콘텐츠를 표시한다.
- 좌측 너비, 우측 최소 너비, 스크롤 방식, 여러 대카테고리 동시 펼침 여부는 아직 미확정이다. 임의의 수치나 동작을 확정하지 않는다.

## 제휴카드 페이지

- 좌측에 등록한 제휴카드를 카드 썸네일 형태로 배치한다.
- 카드를 선택하면 우측에 해당 카드의 기존 이용 가능한 이용권 목록과 혜택을 표시한다.
- 등록 카드가 없으면 좌측에 카드 모양의 박스를 두고 중앙에 + 버튼을 배치해 기존 카드 등록 절차에 연결한다.
- 카드 등록용 문구와 우측 빈 상태 안내는 화면설계서 또는 승인된 문구를 사용한다. 대화에서 제안한 안내 문장을 승인된 원문으로 취급하지 않는다.
- 최초 카드 선택, 카드가 많을 때의 스크롤, 등록 완료 후 선택 방식은 기존 APP 동작을 확인한다. 기준이 없으면 미확정으로 기록한다.

## 접기·펼치기 전환의 필수 원칙

사용자가 현재 보고 있는 콘텐츠를 중심으로 레이아웃을 전환한다. 접으면 현재 작업 중인 APP 버전의 레이아웃에서 해당 콘텐츠를 이어서 보여준다. 첫 화면이나 기본 선택으로 돌아가지 않는다.

유지할 것은 단순한 스크롤 숫자가 아니라 현재 콘텐츠 항목과 항목 안에서 읽던 위치다. 레이아웃이 달라진 뒤에도 해당 콘텐츠가 화면에 보이도록 위치를 맞춘다. 선택 상태·입력 상태도 유지한다.

| 페이지 | 유지할 기준 |
|---|---|
| 마이페이지 | 보고 있던 정보 영역과 해당 영역 내 읽던 위치 |
| 사용처 페이지 | 선택한 대·소카테고리, 메뉴 펼침 상태, 보고 있던 사용처 항목과 위치 |
| 제휴카드 페이지 | 선택한 카드, 보고 있던 이용권 또는 혜택 영역과 읽던 위치 |

예: 펼친 화면에서 특정 카드의 혜택을 읽다가 접으면, 기존 APP 화면에서도 그 카드의 해당 혜택을 보여준다. 카드 선택 목록부터 다시 시작하거나 화면 상단으로 이동시키지 않는다. 반대 방향 전환에도 동일하게 적용한다.

## 작업과 검수

1. 해당 페이지의 기존 APP 화면설계서·디자인·원문·동작을 확인한다.
2. 접힌 APP 화면과 펼친 확장 화면의 콘텐츠 대응을 기록한다.
3. 같은 데이터로 영역만 재배치하고 기존 Shadcn 변수·컴포넌트를 재사용한다.
4. 전환 전 콘텐츠·선택·위치·입력 상태와 전환 후 대응 위치를 명세한다.
5. 양방향 전환의 대표 시나리오를 검수한다. Figma의 배치·프로토타입 확인과 실제 앱의 상태 유지 검증을 구분해 기록한다.
6. 결과 프레임 링크, 적용 범위, 미확정 항목과 실제 구현에서 검증할 사항을 남긴다.

## 추가로 결정할 항목

- 대표 검증 기기와 실제 논리 화면 크기
- 확장 배치로 전환할 가용 너비, 각 영역 최소·최대 너비
- 좌측·우측 스크롤 방식과 좁아졌을 때 콘텐츠 대응
- 세 페이지의 기준 APP·설계서 및 확장 시안 노드 링크

기종별 물리 해상도만으로 전환 기준을 정하지 않는다. 위 항목은 설계·개발 협의 후 기록한다. 현재 기준 Figma 파일은 [TLDS3.0](https://www.figma.com/design/1Qe6U3JD2oHDmofvcKr4ho/TLDS3.0)이며, 세 페이지의 개별 노드 링크는 확인 후 추가한다.
