# AI 공통 사용·팀 인계 안내

기준일: 2026-11-05 · 하네스 v0.5
적용 대상: 디자인 PL, 추가 투입 디자이너, 작업에 사용하는 모든 AI.
ChatGPT·Claude 등 제품명이나 이전 대화의 유무에 관계없이 같은 디자인 규칙을 적용한다. 이 문서는 도구별 기능 제공을 보장하지 않는다.

4. [컴포넌트 목차](components.md), [메인 매칭 기록](main-mapping.md): 원본·사용 상태·변경 근거

## 2. 공통 디자인 규칙과 도구 설정의 경계

| 공통 규칙: AI가 바뀌어도 유지 | 도구별 실행: 작업 시작 시 확인 |
|---|---|
| 원문 유지, 시안 외형 보존, 기존 변수 구조 유지 | 저장소 문서 읽기·쓰기 가능 여부 |
| 기존 Shadcn 수정 및 추가 조합 기준 | Figma 파일·노드·변수 조회 가능 여부 |
| Pretendard와 변수 연결, Dark 보존 | Figma 편집·캡처·폰트 로드 지원 여부 |
| 허용 범위, 검수, 완료·미완료 구분 | 연결 계정·권한·실행 방식·지원하지 않는 기능 |

특정 AI의 도구 이름·명령은 공통 디자인 규칙으로 강제하지 않는다. 실제 환경에서 확인된 실행 방법과 제약은 작업 기록에 남긴다. 다른 AI에서 같은 기능이 있다고 추측하지 않는다.

## 3. 작업 시작 전 기능 확인

- GitHub 문서 본문과 최신 커밋을 실제 읽을 수 있는지 확인한다. 접근이 안 되면 담당자가 제공한 파일의 기준일·커밋을 기록한다.
- Figma 대상 파일과 노드를 실제 조회한다. 조회 성공이 편집 권한까지 보장하지는 않는다.
- 편집 도구가 지원하는 범위, 캡처 가능 여부, Pretendard 및 필요한 굵기의 실제 로드 여부를 확인한다.
- 기존 자료 확인만을 위해 임의 테스트 노드를 만들거나 공유 변수를 변경하지 않는다.
- 읽기만 가능하면 분석·수정 명세까지만 제출한다. 편집을 못 했으면 Figma 적용 완료라고 보고하지 않는다.
- 캡처나 변수 조회가 불가능하면 검수의 제한을 명시한다. 확인하지 못한 내용을 통과로 처리하지 않는다.
- 연결 권한은 각 담당자가 해당 서비스에서 설정한다. 비밀번호·토큰을 문서나 대화에 기입하지 않는다.

## 4. 디자인과 프론트엔드의 확정 역할 분담

- 기존 Shadcn 컴포넌트는 기존 변수 규칙을 유지하며 메인시안에 맞게 수정한다.
- 필요한 추가 컴포넌트는 자유롭게 구성하되 여백·폰트 크기·색상 등 대응되는 기존 변수가 있으면 연결한다.
- 반복 사용하는 조합은 내부 Item 인스턴스를 유지하면서 전체 컴포넌트로 관리한다. 예: Navigation Menu Bar 안에 Navigation Menu Item 인스턴스 배치.
- 전체 조합의 컴포넌트화는 동일 역할의 기초 컴포넌트를 별도로 중복 제작하는 것과 구분한다.
- 기존 변수로 표현하지 못하는 값은 근거·위치·용도를 기록한다. 가까운 값으로 바꿔 시안을 훼손하거나 임의로 시멘틱 토큰을 늘리지 않는다.
- 추가 컴포넌트의 코드 구현 및 시멘틱 이름을 고려한 토큰 시스템 연결은 프론트 개발자가 담당한다.
- 디자인팀은 용도·상태·내부 구성·연결한 변수·미연결 값과 이유를 제공한다. Figma 구성만으로 코드·토큰 매핑이 완료되었다고 보고하지 않는다.

## 5. 확정·예외·미확정 구분

| 상태 | 기록할 내용 | 적용 원칙 |
|---|---|---|
| 확정 | 결정 내용, 적용 범위, 일자, 근거 | 해당 범위에 적용 |
| 승인된 예외 | 기본 규칙, 예외 사유, 대상 노드, 승인 근거 | 다른 화면으로 자동 확대 금지 |
| 미확정 | 질문, 현재 유지값, 영향, 결정 담당자 | AI가 임의 확정하지 않음 |

행간은 2026-11-06 사용자 결정으로 11·12·14px는 150%, 16px 이상은 130%로 확정되었다. 10px는 11px로 변경하며 자간은 -3px다(-3%가 아님). 이 결정은 이전 Auto/150% 미확정 기록보다 우선한다. 특정 시안의 관찰값과 확정 규칙을 구분하고, 기준이 바뀌면 현행 규칙과 과거 기록의 관계를 명시한다.
문서와 실제 Figma가 다르면 최신 승인 근거·버전·적용 범위를 확인한다. 실제 값 또는 최신 날짜라는 이유만으로 자동 우선하지 않는다. 해결되지 않는 부분만 질문하고 영향 없는 작업은 계속한다.

## 6. 디자이너 간 동시 작업과 인계

- 시작 전에 작업 ID, 담당자, 대상 페이지·프레임·컴포넌트 원본, 검토 담당자를 작업 기록에 남긴다.
- 서로 다른 화면을 작업해도 공통 원본·변수를 공유할 수 있다. 원본이나 공통 변수 수정 전 다른 담당자의 작업과 충돌 여부를 확인하고 변경 범위를 공유한다.
- 같은 원본·변수·프레임의 동시 편집은 피한다. 충돌하면 대상별 담당자를 정한 뒤 진행한다.
- 인계에는 기준 커밋·Figma 링크·노드 ID·변경 목록·검수 증거·미완료·예외·다음 작업을 포함한다.
- 다음 작업자는 이전 대화 요약만 믿지 않고 현재 저장소와 Figma를 확인한다.
- 역사적 기록을 덮어 확정처럼 만들지 않는다. 변경된 기준은 현행 문서에 반영하고 이전 결정과의 관계를 이력에 남긴다.
- 담당자 이름·최종 승인자·기준 변경 공유 채널은 팀에서 지정 후 기록한다. AI가 임의 지정하지 않는다.
