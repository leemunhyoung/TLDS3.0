# 디자인 시스템 기준

## 3. 담당자가 준비할 기준 자료

아래 [입력]을 실제 자료로 교체한다. 메인시안 스타일이 아직 미확정이면 기반 정리는 진행할 수 있으나 일괄 스타일 변경은 실행하지 않는다.

| 우선순위 | 항목 | 담당자 입력란 | 완료 조건 |
|---|---|---|---|
| 먼저 | 기준 Shadcn UI | [입력: 파일 URL, 키트 이름·버전 또는 복제일] | 사용할 원본이 하나로 특정됨 |
| 먼저 | 컴포넌트 페이지 | [입력: 페이지 링크] | 알파벳순 구역과 원본을 식별 가능 |
| 먼저 | 변수 구조 | [입력: 컬렉션·모드 목록 및 구조 스냅샷/내보내기 위치] | 실제 파일과 대조 가능 |
| 먼저 | 작업 환경 | [입력: 사용할 AI 도구, Figma 연결 방식, 읽기·쓰기 가능 범위] | 읽기와 편집 가능 여부를 실제 확인 |
| 먼저 | 작업 위치 | [입력: 초안 파일/페이지/섹션 링크, 수정 허용 범위] | AI가 편집할 위치가 특정됨 |
| 메인 반영 전 | 확정 메인시안 | [입력: 프레임별 노드 링크, 채널, 승인일·버전] | 확정안과 참고안이 구분됨 |
| 메인 반영 전 | 스타일 변경표 | [입력: 아래 5절 표] | 확정값과 미확정값이 구분됨 |
| 서브 제작 전 | 화면설계서 | [입력: 위치, 화면 ID, 버전] | 제작 화면과 명세가 대응됨 |
| 서브 제작 전 | 화면 기본 규격 | [입력: 채널·프레임 크기·여백·스크롤·반응형 기준] | 대상 화면에 필요한 범위가 확정됨 |
| 서브 제작 전 | 서비스 정책·용어 | [입력: 확정 자료 링크, 미확정 항목] | AI가 정책을 추측할 필요가 없음 |
| 수정 요청 시 | 고객 요청 | [입력: 요청 원문·일자·대상·확정 여부] | 반영할 요청과 논의 중인 요청이 구분됨 |
| 운영 시작 전 | 검토 담당자 | [입력: 디자인 기준 승인자와 작업 검수자] | 누가 승인하는지 명확함 |

각 자료에는 버전 또는 기준일을 기록한다. 링크를 읽을 수 없다면 필요한 자료를 접근 가능한 형태로 제공한다. AI는 읽지 못한 자료를 확인했다고 보고하지 않는다.

## 5. 메인시안 변경 매핑표

현재 값은 실제 기준 파일에서 확인한다. 기존 변수명을 추측하여 입력하지 않는다.

| 대상 속성/컴포넌트 | 현재 변수 경로·값 또는 원본 속성 | 메인시안 기준값·근거 링크 | 변경 방법 | 영향 범위 | 확정 여부 |
|---|---|---|---|---|---|
| [입력] | [입력] | [입력] | 변수 값/변수 연결/원본 디자인 수정 | [입력] | 확정/확인 필요 |

메인시안에서 보이는 스타일과 컴포넌트 전체 상태를 구분한다. 예를 들어 기본 버튼의 스타일만 확정되었다면 오류·비활성·포커스 상태를 임의로 확정하지 않는다. 기존 상태 유지 또는 추가 제안으로 표시한다.

## 현재 서체 기준

- 제품 서체: Pretendard. 2026-11-03 사용자가 Figma 계정에 굵기 파일을 업로드했고 AI 연결 환경에서 9개 굵기 인식을 확인했다. 세션별 실제 로드는 다시 확인한다.
- 기존 `family/sans`, `family/mono`, `family/sans-serif`, `family/monospace` 값은 Pretendard로 통일했다. 변수 이름·구조는 유지한다. mono 계열도 제품의 통일 서체를 사용하므로 고정폭 특성은 유지되지 않는다.
- Weight: 기존 `weight/normal` 400, `weight/medium` 500, `weight/semibold` 600, `weight/bold` 700 등을 사용한다. 실제 변수 값과 적용 굵기를 확인한다.
- Pretendard의 실제 스타일명은 Regular·Medium·SemiBold·Bold 등이다. 기존 표시 이름과 글꼴 로드에 쓰는 스타일명이 같다고 가정하지 않는다.
- 로컬 설치만 되어 있는 폰트는 서버 연결에서 보이지 않을 수 있다. Figma 파일 목록 → 프로필 → Settings → Account → Your uploaded fonts에서 사용하는 TTF/OTF와 굵기를 업로드한 뒤 재확인한다.
- 기준일 잔여 예외: 키트 소개 배너의 Courier New 텍스트 8개는 기존 폰트 로드 불가로 미변경 상태다. 실제 UI 컴포넌트와 구분해 추적하며, 전체 파일 서체 변경 완료로 간주하지 않는다.

## 지원 언어와 기본 읽기 방향 — 2026-11-05 확정

- 더 라운지 앱의 디자인 지원 언어는 국문·영문이다. 두 언어 모두 기본 읽기 방향은 왼쪽에서 오른쪽이다.
- 고객용 컴포넌트에서는 LTR/RTL 선택 속성과 LTR·RTL 안내 표기를 제공하지 않는다. 기본 방향을 고정하고 실제 필요한 상태만 노출한다.
- RTL을 신규 제작하거나 복원하지 않는다. 향후 지원 언어 확대가 명시적으로 승인되면 별도 검토한다.
- 읽기 방향과 정렬·배치는 구분한다. 좌측/중앙 정렬, 구분선의 가로/세로, 아이콘의 좌우 배치 등 필요한 속성을 방향 정리라는 이유로 삭제하지 않는다.
- RTL 원본 145개는 과거 참조를 보호하기 위해 [보관 페이지](https://www.figma.com/design/1Qe6U3JD2oHDmofvcKr4ho/TLDS3.0?node-id=5124-12846)로 이동했다. 고객용·신규 작업 자산으로 사용하지 않는다. 과거 Delete 페이지 등 보관 자료의 참조는 유지한다.
- 현행 Components의 기본 원본 ID·변수·Light/Dark 설정을 보존한다. 방향 속성이 없어졌다고 인스턴스를 분리하거나 변수를 제거하지 않는다.


## 타이포그래피 확정 규칙 — 2026-11-06

- 10px는 신규 사용하지 않으며 현행 작업 대상의 10px 텍스트는 11px로 변경한다.
- 11px·12px·14px: 행간 150%.
- 16px 이상: 행간 130%.
- 자간은 모든 대상 크기에서 **0px**로 통일한다. 2026-11-06 후속 사용자 결정으로 이전 -3px 지정을 대체한다.
- 이 결정은 기존 Auto/150% 미확정 및 개별 버튼 Auto 행간 기록보다 우선한다. 13px·15px 등 명시되지 않은 크기는 임의 확정하지 않는다.
- Family·Weight·Size의 기존 변수 구조를 유지한다. 10px 대신 기존 size/11을 연결하고, 자간은 tw/font의 tracking/tlds(0px)를 사용한다. tracking/normal의 원시값을 임의 변경하지 않는다.
- 행간은 Figma의 PERCENT 값을 사용한다. 기존 px 행간 변수는 연결을 해제하고 승인된 비율값을 적용한다. %를 px 변수에 그대로 넣거나 의미가 다른 변수에 억지로 연결하지 않는다.
- 적용 대상은 현행 재사용 컴포넌트 원본과 현재 작업 화면이다. 화면설계서·참고 시안·보관 페이지는 직접 편집하지 않는다. 공유 원본 변경으로 인한 인스턴스 반영은 직접 편집과 구분한다.
- 타이포 변경 후 버튼·배지·메뉴·카드·폼의 줄바꿈, 잘림, 겹침과 정렬을 확인한다. 명시적으로 승인된 타이포 변경 외 문구·아이콘·색상·순서를 임의로 바꾸지 않는다.


### 자간 기준 변경 — 2026-11-06

사용자 후속 요청으로 자간을 0px로 통일한다. 이전 -3px 규칙을 대체한다. Figma tw/font의 tracking/tlds 값은 0이며, 기존 연결을 유지한다. 10px→11px 및 크기별 행간(11·12·14px=150%, 16px 이상=130%)은 유지한다.
