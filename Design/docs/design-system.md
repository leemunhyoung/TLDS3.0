# 디자인 시스템 기준

## 3. 담당자가 준비할 기준 자료

아래 [입력]을 실제 자료로 교체한다. 메인시안 스타일이 아직 미확정이면 기반 정리는 진행할 수 있으나 일괄 스타일 변경은 실행하지 않는다.

| 우선순위 | 항목 | 담당자 입력란 | 완료 조건 |
|---|---|---|---|
| 먼저 | 기준 Shadcn UI | [입력: 파일 URL, 키트 이름·버전 또는 복제일] | 사용할 원본이 하나로 특정됨 |
| 먼저 | 컴포넌트 페이지 | [입력: 페이지 링크] | 알파벳순 구역과 원본을 식별 가능 |
| 먼저 | 변수 구조 | [입력: 컬렉션·모드 목록 및 구조 스냅샷/내보내기 위치] | 실제 파일과 대조 가능 |
| 먼저 | 작업 환경 | [입력: 사용할 AI 도구, Figma 연결 방식, 읽기·쓰기 가능 범위] | 읽기와 편집 가능 여부를 실제 확인 |
| 먼저 | 작업 위치 | [입력: 초안 파일/페이지/섹션 링크, 수정 허용 범위] | AI가 편집할 위치가 특정됨 |
| 메인 반영 전 | 확정 메인시안 | [입력: 프레임별 노드 링크, 채널, 승인일·버전] | 확정안과 참고안이 구분됨 |
| 메인 반영 전 | 스타일 변경표 | [입력: 아래 5절 표] | 확정값과 미확정값이 구분됨 |
| 서브 제작 전 | 화면설계서 | [입력: 위치, 화면 ID, 버전] | 제작 화면과 명세가 대응됨 |
| 서브 제작 전 | 화면 기본 규격 | [입력: 채널·프레임 크기·여백·스크롤·반응형 기준] | 대상 화면에 필요한 범위가 확정됨 |
| 서브 제작 전 | 서비스 정책·용어 | [입력: 확정 자료 링크, 미확정 항목] | AI가 정책을 추측할 필요가 없음 |
| 수정 요청 시 | 고객 요청 | [입력: 요청 원문·일자·대상·확정 여부] | 반영할 요청과 논의 중인 요청이 구분됨 |
| 운영 시작 전 | 검토 담당자 | [입력: 디자인 기준 승인자와 작업 검수자] | 누가 승인하는지 명확함 |

각 자료에는 버전 또는 기준일을 기록한다. 링크를 읽을 수 없다면 필요한 자료를 접근 가능한 형태로 제공한다. AI는 읽지 못한 자료를 확인했다고 보고하지 않는다.

## 5. 메인시안 변경 매핑표

현재 값은 실제 기준 파일에서 확인한다. 기존 변수명을 추측하여 입력하지 않는다.

| 대상 속성/컴포넌트 | 현재 변수 경로·값 또는 원본 속성 | 메인시안 기준값·근거 링크 | 변경 방법 | 영향 범위 | 확정 여부 |
|---|---|---|---|---|---|
| [입력] | [입력] | [입력] | 변수 값/변수 연결/원본 디자인 수정 | [입력] | 확정/확인 필요 |

메인시안에서 보이는 스타일과 컴포넌트 전체 상태를 구분한다. 예를 들어 기본 버튼의 스타일만 확정되었다면 오류·비활성·포커스 상태를 임의로 확정하지 않는다. 기존 상태 유지 또는 추가 제안으로 표시한다.
