# 02-subpage-design

먼저 [공통 규칙](../AGENTS.md)과 [디자인 시스템 기준](../docs/design-system.md)을 읽는다.

## 8. 작업 B — 서브페이지 디자인

### 입력

확정 디자인 시스템 버전, 화면설계서·화면 ID, 대상 채널·규격, 승인된 유사 화면, 정책·용어, 작업 위치.

### 수행

1. 화면설계서의 필수 정보·기능·상태를 목록화한다.
2. 기존 컴포넌트와 화면 패턴에 대응시킨다.
3. 디자인 시스템의 인스턴스를 우선 사용하여 화면을 제작한다.
4. 새로운 컴포넌트나 패턴이 필요하면 기존 것으로 해결할 수 없는 이유를 기록한다.
5. 설계서와 결과를 대조하고 관련 상태·스크롤·규격을 확인한다.

### 완료 조건

- 필수 정보와 기능이 누락되지 않는다.
- 기준 변수와 컴포넌트가 적용된다.
- 화면설계서에 없는 정책·기능을 확정사항으로 추가하지 않는다.
- 신규 제안과 미확정 사항이 구분된다.
- 해당 화면에서 사용한 컴포넌트를 목차에 기록한다.


작업 기록은 [양식](../tasks/TEMPLATE.md)을 사용한다.

## 원문 대응 및 완료 검수

1. [현재 Figma 위치](../docs/design-system.md#현재-figma-위치)에서 소스와 결과 페이지를 구분하고 소스 화면 ID → 결과 프레임 링크 대응표를 작업 기록에 남긴다.
2. 화면별 원문을 먼저 확보한다. 제목·본문·버튼·플레이스홀더·예시값을 포함하며, 숫자를 일괄 제거해 전화번호나 인증번호까지 누락시키지 않는다.
3. 원문의 표기와 의미를 유지해 기존 Shadcn 인스턴스로 구성한다. 미확정 메인 스타일을 기다리는 구조 시안이라면 상태를 명시한다.
4. 누락된 항목은 임의 생성·전용하지 않는다. 공통 화면 재사용은 근거와 범위를 확인받는다. 독립적으로 진행 가능한 화면은 계속한다.
5. 원문에 없는 개선 설명, 서비스명 교정, 임의의 샘플 데이터는 결과 화면에 넣지 않는다. 질문과 제안은 작업 기록에 남긴다.
6. 새 텍스트의 Family·Weight·Size 등 기존 변수를 연결한다.
7. [공통 검수표](../docs/quality-checklist.md)에 따라 원문과 결과의 누락·추가를 양방향으로 대조하고 실제 화면도 확인한다.

## 폴드 확장 배치 작업

대상 여부를 [폴드폰 대응 기준](../docs/foldable.md)에서 확인한다. 적용 예상 페이지를 작업할 때는 기존 APP → 펼친 확장 배치의 콘텐츠 대응표와 접기·펼치기 시나리오를 작성한다. 동일 데이터와 기능을 사용하고, 접으면 현재 APP에서 보고 있던 콘텐츠를 이어서 표시한다. 그 외 페이지는 기존 반응형 기준을 따른다. 배치 검수만으로 실제 앱의 전환·상태 유지까지 통과했다고 보고하지 않는다.
