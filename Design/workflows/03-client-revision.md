# 03-client-revision

먼저 [공통 규칙](../AGENTS.md)과 [디자인 시스템 기준](../docs/design-system.md)을 읽는다.

## 9. 작업 C — 고객 수정사항 반영

### 입력

요청 원문, 요청 ID·일자, 대상 화면/노드, 반영하기로 확정된 범위, 현재 디자인 시스템·설계서 버전.

### 수행

1. 요청을 항목별로 나누고 완료 조건을 정리한다.
2. 화면 한 곳의 변경인지, 반복 패턴인지, 공통 컴포넌트·변수 변경인지 분류한다.
3. 공통 변경은 영향을 확인한다. 영향이 요청 범위를 벗어나면 먼저 확인한다.
4. 확정된 요청을 반영하고 해당 항목별로 검수한다.
5. 변경 전후, 영향받은 대상, 기준 문서 갱신 필요 여부를 기록한다.

### 완료 조건

- 확정된 요청이 반영되며 관계없는 부분을 임의로 바꾸지 않는다.
- 원본 수정에 따른 다른 인스턴스의 영향을 확인한다.
- 일회성 예외를 공통 기준으로 무단 확장하지 않는다.
- 고객 요청과 기존 기준의 충돌 및 미반영 사유가 기록된다.


작업 기록은 [양식](../tasks/TEMPLATE.md)을 사용한다.

## 문구 변경과 재검수

고객 요청으로 원문을 변경할 때는 요청 원문·승인 범위·기존 문구·변경 문구를 기록한다. 승인된 한 문구의 변경을 다른 화면 전체로 무단 확장하지 않는다. 원문 기준이 바뀌면 기준 버전과 영향받은 화면을 함께 기록한다.

변경 후 [공통 검수표](../docs/quality-checklist.md)를 적용한다. 수정 대상뿐 아니라 영향을 받은 인스턴스·줄바꿈·변수 연결도 확인하고, 미반영 및 임시 적용을 구분한다.

## 업무 연결과 결과 기록

요청 범위와 필요한 자료는 [업무 시작점](AGENTS.md)에서 확인합니다. 위 디자인 절차와 보호·검수 기준은 유지합니다. 결과는 [상세 양식](../tasks/TEMPLATE.md) 또는 [간단 기록](../tasks/README.md#간단-기록)으로 남기고 수정 작업의 이력 목차를 갱신합니다. 개발 전달이 있으면 [팀 인계 안내](../docs/ai-collaboration.md)에 따라 구현 차이와 미검증 범위를 기록합니다.
