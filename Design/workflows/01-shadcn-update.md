# 01-shadcn-update

먼저 [공통 규칙](../AGENTS.md)과 [디자인 시스템 기준](../docs/design-system.md)을 읽는다.

## 7. 작업 A — 메인시안에 맞춘 Shadcn UI 수정

### 입력

기준 Shadcn UI, 확정 메인시안, 변수 구조, 변경 매핑표, 대상 컴포넌트 목록, 작업 허용 범위.

### 수행

1. 현재 구조와 메인시안을 비교한다.
2. 변경을 변수 값 변경, 기존 변수 연결 수정, 컴포넌트 원본 수정으로 구분한다.
3. 확정된 변수 값을 적용하고 대표 컴포넌트에서 영향을 확인한다.
4. 요청된 컴포넌트의 구조·레이아웃·상태를 수정한다.
5. 기본 상태뿐 아니라 기존 Variant와 관련 모드를 확인한다.
6. 미확정 상태와 기존 구조로 해결하기 어려운 요구를 별도로 보고한다.

### 완료 조건

- 요청 범위가 메인시안의 확정 기준과 일치한다.
- 기존 변수 구조와 참조 관계가 유지된다.
- 변수 연결과 원본/인스턴스 관계가 의도치 않게 끊기지 않는다.
- 텍스트 잘림, 여백 오류, 상태 누락이 없다.
- 공통 값 변경으로 영향을 받은 대상과 검수하지 못한 범위가 기록된다.


작업 기록은 [양식](../tasks/TEMPLATE.md)을 사용한다.

## 추가 필수 확인

- 작업 전에 지정 글꼴과 굵기를 로드하고 현재 변수·인스턴스 연결을 기록한다.
- 새로 만드는 텍스트와 보조 요소도 기존 변수 구조에 맞춰 연결한다.
- 스타일 변경 요청을 이유로 역할·동작·상태나 제품 문구를 임의 변경하지 않는다.
- 현재 Light 모드를 기준으로 작업하되 Dark 설정과 별칭 관계를 보존한다.
- [공통 검수표](../docs/quality-checklist.md)를 적용하고 검수하지 못한 Variant·모드·배너 등은 별도 보고한다.

## 업무 연결과 결과 기록

요청 범위와 필요한 자료는 [업무 시작점](AGENTS.md)에서 확인합니다. 위 디자인 절차와 보호·검수 기준은 유지합니다. 결과는 [상세 양식](../tasks/TEMPLATE.md) 또는 [간단 기록](../tasks/README.md#간단-기록)으로 남기고 수정 작업의 이력 목차를 갱신합니다. 개발 전달이 있으면 [팀 인계 안내](../docs/ai-collaboration.md)에 따라 구현 차이와 미검증 범위를 기록합니다.
