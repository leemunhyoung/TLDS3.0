# TLDS3.0 디자인 업무 안내

기존 디자인 기준을 확인하고, 이번 요청에 맞는 업무 절차와 기록으로 이어갑니다.

## 01. 시작하기

디자인 규칙·수치·변수·결정·이력은 TLDS3.0을 기준으로 합니다. Desing_guide는 문서 템플릿·워크플로우 구성·사람용 진입점의 참고 자료입니다.

- [디자인팀 시작 안내](README.md): 읽는 순서와 기존 기준을 확인합니다.
- [디자인 AI 규칙](AGENTS.md): 디자인 작업의 허용 범위·보호·검수 원칙을 확인합니다.
- [요청별 업무 시작점](workflows/AGENTS.md): 이번 요청에 필요한 자료와 절차를 선택합니다.
- [프로젝트 공통 가이드](https://idtloungepmo.github.io/lounge3.0_guide/): 공통 운영과 문서 작성 기준을 확인합니다.

자료의 위치를 전달한 것과 실제로 내용을 읽은 것은 구분합니다. 현재 문서·Figma·도구 접근 상태는 작업마다 확인합니다.

## 04. 요청과 결과 남기기

AI에는 공통·파트 지침의 실제 위치와 이번 대상·범위를 함께 전달합니다. 아래 항목을 이번 작업에 맞게 채웁니다.

```text
프로젝트 공통: <공통 가이드의 AGENTS.md 경로 또는 링크>
디자인 파트: <TLDS3.0의 AGENTS.md와 Design/AGENTS.md 경로>
대상·범위: <문서 또는 Figma 파일·페이지·노드>
요청: <검토·수정·개발 전달·검수 중 이번 범위>
기준 자료: <설계서·시안·버전·관련 결정>
수정 허용 범위·보호 대상: <변경할 대상과 유지할 내용>
공유 기록: <기존 작업 기록 위치>

TLDS3.0을 디자인 기준으로 필요한 문서와 원본을 실제로 확인해 주세요.
업무 시작점에서 이번 요청에 맞는 절차를 선택하고,
변경·실제 검증·미정·미확인·다음 작업을 남겨 주세요.
```

- [상세 요청·결과 양식](tasks/TEMPLATE.md): 공통 원본·변수 변경이나 여러 화면의 영향을 관리합니다.
- [간단 기록](tasks/README.md#간단-기록): 작은 수정의 요청·변경·검증·다음 작업을 남깁니다.

승인된 결정, 문서 반영, Figma 반영, 개발 구현, 실제 동작 검증을 각각 구분합니다.

## 05. 개발과 함께 확인하기

디자인팀은 화면·컴포넌트의 용도·종류·크기·상태·내부 구성·연결 변수·미연결 값과 이유를 전달합니다. 코드 구현과 의미 토큰 매핑은 기존 역할 분담에 따라 개발자가 담당합니다.

기존 Figma 변수 구조와 승인 값을 유지합니다. 현재 프론트·토큰·Storybook의 실제 자료와 버전을 지정해 차이를 확인하고, 변경이 필요한 내용은 영향 범위와 함께 협의합니다.

Figma와 Storybook 비교, 실제 앱의 화면 이동·데이터·권한·Native 동작 검증은 각각 확인한 범위를 남깁니다. 필요한 상태·너비·키보드·접근성 항목은 [공통 검수표](docs/quality-checklist.md)에서 선택합니다.
