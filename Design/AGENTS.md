# 디자인팀 AI 공통 규칙

## AI 종류와 관계없이 적용

이 문서는 ChatGPT·Claude 등 특정 AI에 종속되지 않는 디자인팀 공통 기준이다. 자동으로 읽힌다고 가정하지 말고 작업 시작 시 본문과 관련 문서를 실제 확인한다. [AI 공통 사용·팀 인계 안내](docs/ai-collaboration.md)에 따라 도구 기능을 별도로 확인하고, 확인 불가·미편집을 완료로 보고하지 않는다. 이전 대화는 필수 입력이 아니며 결정은 공유 문서에 기록한다.

## 1. 목적과 작업 범위

AI는 다음 세 가지 작업을 수행한다.

1. Shadcn UI 기반 디자인 시스템을 확정 메인시안에 맞게 수정한다.
2. 수정된 디자인 시스템과 화면설계서를 사용하여 서브페이지를 디자인한다.
3. 고객 요청에 따른 수정사항을 반영한다.

작업 순서: Shadcn UI 기반 구축 → 메인시안 반영 → 서브페이지 제작 → 사용 여부 확인 → 미사용 컴포넌트 정리. 고객 수정은 각 단계에서 발생할 수 있다.

## 2. 현재 합의된 공통 규칙

- Shadcn UI를 디자인 시스템의 기반으로 사용한다.
- 기존 변수 구조와 의미를 유지하며 그 구조에 맞춰 컴포넌트를 수정한다.
- 메인시안에 따라 변수 값을 변경할 수 있다. 변경은 요청된 범위와 영향 검토를 따른다.
- 변수의 컬렉션·그룹·이름·모드·타입·별칭 참조 관계를 임의로 변경하거나 삭제하지 않는다. 실제 구조는 기준 파일을 확인한다.
- 색상이 비슷하다는 이유만으로 서로 다른 역할의 변수를 통합하지 않는다.
- 기존에 변수로 관리되는 속성의 연결을 임의로 끊지 않는다. 기존 변수에 없는 속성까지 억지로 연결하지 않는다.
- 기존 구조로 표현할 수 없는 요구는 예외 또는 확장 제안으로 기록하고 검토받는다.
- 컴포넌트는 한 페이지에서 기존 이름을 기준으로 알파벳순으로 정리한다. 이 순서는 탐색용이며 수정 순서를 강제하지 않는다.
- 현재 단계에서 사용 여부를 이유로 컴포넌트를 임의로 삭제하지 않는다. 추후 실제 사용 범위가 확인되면 정리한다.
- 컴포넌트 정리와 변수 정리를 분리한다. 컴포넌트 삭제를 이유로 공유 변수를 함께 삭제하지 않는다.
- 원본 컴포넌트와 인스턴스 관계, 기존 속성 및 상태를 유지한다. 변경이 필요하면 영향을 기록한다.
- 메인시안에 없는 정책·상태·반응형 규칙은 확정 사실로 만들지 않는다.

## 3. 문구와 누락 정보

- 화면설계서의 제목·본문·버튼·탭·플레이스홀더·예시값·날짜·마스킹·타이머 문구를 원문 그대로 사용한다. 보기 좋게 다듬거나 서비스명을 임의 교정하지 않는다.
- 오탈자, 정책과 표시값의 충돌은 결과 화면 밖의 작업 기록에 원문·위치·질문을 남긴다. 사용자가 명시적으로 승인한 변경만 해당 범위에 적용한다.
- 다른 화면의 문구나 입력 항목을 근거 없이 가져오지 않는다. 설계서 누락은 표시하고, 공통 화면 재사용은 근거와 대상 범위를 제시해 확인받는다. 기존 승인 범위는 다시 승인받지 않는다.
- 기능·상태·입력 항목·동의 항목의 의미를 유지한다. 설명 문구를 체크박스나 버튼으로 바꾸지 않는다.

## 4. 글꼴과 변수 연결

- 작업 전에 AI 연결 환경에서 Pretendard와 필요한 굵기를 실제로 로드한다. 사용자 PC에서 표시된다는 사실만으로 사용 가능하다고 판단하지 않는다.
- 불러올 수 없으면 영향받는 작업을 보류하고 이유를 보고한다. 대체 글꼴을 임의로 적용하거나 완료로 보고하지 않는다. 독립적으로 진행 가능한 작업은 계속한다.
- 새 제목·본문·안내·라벨도 기존 Family·Weight·Size 및 해당하는 Line height·Letter spacing·Color 변수를 연결한다. 이미 사용 가능한 변수가 있는 속성을 직접 지정한 값으로 끝내지 않는다.
- 변수의 숫자 값과 화면에 적용된 실제 글꼴·굵기를 함께 검증한다. 혼합 스타일 텍스트는 구간별로 확인한다.
- 기존 인스턴스의 변수 연결을 유지한다. 동일 목적의 변수를 중복 생성하지 않는다.

## 5. 편집 범위와 완료 기준

- 시작 전에 소스 페이지·결과 페이지·허용 노드·보호 대상을 구분한다. [현재 Figma 위치](docs/design-system.md#현재-figma-위치)를 확인한다.
- 화면설계서·참고 시안·검토 전용 페이지는 읽기 전용으로 취급한다. 수정은 별도 명시된 요청에 한한다.
- 변경에 필요한 부분만 수정한다. 단순 문구·폰트 변경 때문에 프레임 전체나 무관한 요소를 재생성하지 않는다.
- [공통 검수표](docs/quality-checklist.md)를 필수로 적용한다. 미검수·불일치·임시 적용이 남으면 전체 완료로 표시하지 않는다.
- 결과는 완료·미완료·임시 적용으로 구분하고, 링크와 노드 ID·예외 사유·검수 범위를 기록한다.

## 6. 모든 작업에 적용할 실행 절차

1. 작업 요청과 관련 기준 자료의 버전을 읽는다. [컬러 변경 확인](docs/colors.md)에 따라 실제 Figma 컬러 변수·HEX·모드·별칭과 현재 기준표를 작업 전에 대조한다.
2. 실제 대상, 변수 연결, 컴포넌트 관계를 확인한다.
3. 수정 범위와 다른 화면에 미칠 영향을 정리한다.
4. 허용 범위 안에서 작업한다. 공통 변수 변경은 공유된 영향 범위까지 확인한다.
5. 해당 작업의 검수표에 따라 확인하고 문제를 수정한다.
6. 결과 링크, 변경 내용, 검수 결과, 미확정 사항을 제출한다.

기준이 충돌하면 먼저 확정 여부·버전·적용 범위를 비교한다. 해결되지 않으면 영향받는 부분을 임의로 결정하지 않고 질문한다. 영향 없는 작업은 계속할 수 있다.

운영 제안: 초안 위치에서 대표 컴포넌트와 대표 화면을 검토한 뒤 나머지로 확장한다. 초안 위치로 복제할 때도 기존 변수와 컴포넌트 참조가 유지되는지 확인한다. 이 운영 방식은 담당자가 확정한다.

## 폴드폰 대응

[폴드폰 대응 기준](docs/foldable.md)을 적용한다. 적용 예상 페이지는 제휴카드 페이지·마이페이지·사용처 페이지이며, 동일 데이터·기능으로 배치만 변경한다. 접으면 현재 APP 레이아웃에서 보고 있던 콘텐츠를 이어서 표시한다. 접기·펼치기 양방향으로 콘텐츠·선택·읽던 위치·입력 상태를 유지한다. 나머지 페이지는 기존 반응형 기준을 적용한다. 미확정 전환 너비나 동작은 임의로 확정하지 않는다.

## 컬러 기준 변경 확인

모든 작업은 [컬러 기준](docs/colors.md)을 먼저 확인한다. 실제 Figma 값과 문서의 차이를 조사하고, 사용자 승인 근거가 없는 변경은 임의 복원·확정하지 않는다. 승인된 변경은 기준표·컬러 버전·변경 이력에 반영한다. Primary는 Light에서 indigo/500을 참조하며, Brand Color 1·별도 CTA 역할을 새로 적용하지 않는다. Dark 모드와 기존 공유 변수는 보존한다.

## 기존 Shadcn 원본 수정 우선 — 2026-11-05

메인의 디자인 요소는 기존 Shadcn 컴포넌트 원본의 스타일·필요 상태를 수정한 뒤, 화면 요소를 해당 원본의 인스턴스로 교체한다. 동일 역할의 컴포넌트가 있는데 별도 더 라운지 컴포넌트를 병행 생성하거나 이름만 별도로 붙이지 않는다. 기존 역할·변수 구조·필요한 상태와 원본 ID를 가능한 범위에서 유지한다. 대응되는 원본이 없거나 기존 구조로 해결할 수 없는 경우에만 이유·재사용 범위·영향을 기록하고 확장을 제안한다. 원본 수정 후 화면 인스턴스의 문구·상태·레이아웃과 다른 참조 화면의 영향을 확인한다.


## 컴포넌트 교체 시 시안 디자인 보존 — 2026-11-05

컴포넌트 교체는 구조와 재사용성을 정리하는 작업이며, 시안을 재디자인하는 작업이 아니다. 사용자가 요청하거나 승인한 변경 범위를 제외하고 기준 시안의 외형을 임의로 변경하지 않는다. Shadcn 기본 스타일이나 Auto Layout 기본값을 이유로 시안의 디자인을 바꾸지 않는다.

### 교체 전
- 해당 작업 시점의 기준 시안·페이지·노드 ID와 비교용 캡처를 확보한다. 원본 또는 비교용 사본은 보존한다.
- 대상의 전체 크기, 내부 여백, 요소 간 간격, 정렬, 텍스트 크기·굵기·행간·자간, 색상, 테두리·라운드·효과와 현재 상태를 확인한다.
- 프레임 높이뿐 아니라 내부 텍스트 영역의 실제 크기와 위치, Hug / Fill / Fixed, 정렬 및 줄바꿈 설정을 확인한다.

### 교체 및 검수
- 기존 Shadcn 원본을 수정하고 인스턴스로 교체하되 기준 시안의 외형을 유지한다. 구조 변경과 시각적 변경을 구분한다.
- 기존 변수 연결은 유지한다. 변수 적용으로 외형이 달라지면 가까운 값으로 임의 타협하지 않고, 구조·연결 오류를 먼저 수정한다. 기존 변수로 표현할 수 없는 값은 예외와 필요한 확장으로 기록한다.
- 교체 후 같은 화면 폭·모드·상태·배율에서 기준 시안과 나란히 비교하거나 겹쳐 확인한다. 실제 캡처와 수치를 함께 검수한다.
- 전체 크기가 같더라도 내부 요소의 위치와 간격이 달라졌으면 일치로 판단하지 않는다. Default·Active 등 적용한 상태를 각각 확인한다.
- Navigation Menu 사례: 메뉴 높이 48px가 같아도 텍스트 영역이 24px에서 48px Fill로 늘어나면 글자가 위로 이동하고 Active Bar와의 간격이 달라진다. 텍스트 영역 높이·세로 위치·Bar 위치와 두 요소 사이 간격까지 대조한다. 이 수치는 해당 사례의 기준이며 다른 컴포넌트에 일괄 강제하지 않는다.
- 공통 원본 수정이 다른 인스턴스에 미치는 영향을 확인한다. 의도하지 않은 차이는 완료 전에 수정한다.
- 외형 유지가 불가능하거나 디자인 변경이 필요하면 해당 부분을 임의 확정하지 않는다. 원본 대비 차이·원인·영향·대안을 제시해 확인받고, 독립적으로 가능한 작업은 계속한다.
- 결과에 기준/결과 노드 ID, 비교 캡처, 검수한 상태·항목, 승인된 변경과 미해결 차이를 기록한다. 미검수 또는 의도하지 않은 디자인 차이가 남으면 교체 완료로 보고하지 않는다.

이 항목은 [공통 검수표](docs/quality-checklist.md)의 구조·실제 화면 캡처 검수와 함께 필수 적용한다.

## 추가 컴포넌트와 개발 연결 — 2026-11-05

기존 Shadcn 컴포넌트는 기존 변수 규칙을 유지하며 수정한다. 필요한 추가 컴포넌트는 자유롭게 구성하되 여백·폰트 크기·색상 등 대응되는 기존 변수를 연결한다. 반복되는 전체 조합(예: Navigation Menu Bar)은 내부 Item 인스턴스를 유지하는 상위 컴포넌트로 관리할 수 있다. 이는 동일 역할의 기초 컴포넌트 중복 제작과 구분하며, 위의 ‘기존 Shadcn 원본 수정 우선’ 규칙과 함께 적용한다. 추가 컴포넌트의 코드 구현 및 시멘틱 이름을 고려한 토큰 매핑은 프론트 개발자가 담당한다. 디자인팀은 용도·상태·연결 변수·미연결 값과 이유를 기록한다. 세부 기준은 [팀 인계 안내](docs/ai-collaboration.md)를 따른다.


## 지원 언어와 기본 읽기 방향 — 2026-11-05 확정

- 더 라운지 앱의 디자인 지원 언어는 국문·영문이다. 두 언어 모두 기본 읽기 방향은 왼쪽에서 오른쪽이다.
- 고객용 컴포넌트에서는 LTR/RTL 선택 속성과 LTR·RTL 안내 표기를 제공하지 않는다. 기본 방향을 고정하고 실제 필요한 상태만 노출한다.
- RTL을 신규 제작하거나 복원하지 않는다. 향후 지원 언어 확대가 명시적으로 승인되면 별도 검토한다.
- 읽기 방향과 정렬·배치는 구분한다. 좌측/중앙 정렬, 구분선의 가로/세로, 아이콘의 좌우 배치 등 필요한 속성을 방향 정리라는 이유로 삭제하지 않는다.
- RTL 원본 145개는 과거 참조를 보호하기 위해 [보관 페이지](https://www.figma.com/design/1Qe6U3JD2oHDmofvcKr4ho/TLDS3.0?node-id=5124-12846)로 이동했다. 고객용·신규 작업 자산으로 사용하지 않는다. 과거 Delete 페이지 등 보관 자료의 참조는 유지한다.
- 현행 Components의 기본 원본 ID·변수·Light/Dark 설정을 보존한다. 방향 속성이 없어졌다고 인스턴스를 분리하거나 변수를 제거하지 않는다.


## 타이포그래피 확정 규칙 — 2026-11-06

- 10px는 신규 사용하지 않으며 현행 작업 대상의 10px 텍스트는 11px로 변경한다.
- 11px·12px·14px: 행간 150%.
- 16px 이상: 행간 130%.
- 자간은 모든 대상 크기에서 **0px**로 통일한다. 2026-11-06 후속 사용자 결정으로 이전 -3px 지정을 대체한다.
- 이 결정은 기존 Auto/150% 미확정 및 개별 버튼 Auto 행간 기록보다 우선한다. 13px·15px 등 명시되지 않은 크기는 임의 확정하지 않는다.
- Family·Weight·Size의 기존 변수 구조를 유지한다. 10px 대신 기존 size/11을 연결하고, 자간은 tw/font의 tracking/tlds(0px)를 사용한다. tracking/normal의 원시값을 임의 변경하지 않는다.
- 행간은 Figma의 PERCENT 값을 사용한다. 기존 px 행간 변수는 연결을 해제하고 승인된 비율값을 적용한다. %를 px 변수에 그대로 넣거나 의미가 다른 변수에 억지로 연결하지 않는다.
- 적용 대상은 현행 재사용 컴포넌트 원본과 현재 작업 화면이다. 화면설계서·참고 시안·보관 페이지는 직접 편집하지 않는다. 공유 원본 변경으로 인한 인스턴스 반영은 직접 편집과 구분한다.
- 타이포 변경 후 버튼·배지·메뉴·카드·폼의 줄바꿈, 잘림, 겹침과 정렬을 확인한다. 명시적으로 승인된 타이포 변경 외 문구·아이콘·색상·순서를 임의로 바꾸지 않는다.


### 자간 기준 변경 — 2026-11-06

사용자 후속 요청으로 자간을 0px로 통일한다. 이전 -3px 규칙을 대체한다. Figma tw/font의 tracking/tlds 값은 0이며, 기존 연결을 유지한다. 10px→11px 및 크기별 행간(11·12·14px=150%, 16px 이상=130%)은 유지한다.


## 작업 종료 시 이력 기록 — 2026-11-09

작업 종료 시 [작업 기록 목차](tasks/README.md)에 따라 요청·변경·대상 링크·근거·실제 검증 범위·남은 작업을 기록합니다. 검수 결과는 확인·확정된 범위만 적고 미확정 값은 빈칸으로 남깁니다. 반영 상태와 사용자 승인·개발 구현·실제 동작 검증을 구분합니다. 새 기록을 만들면 목차도 함께 갱신합니다. 과거 작업의 검증이나 승인 여부를 추측해 채우지 않습니다.

## 요청별 시작과 문서 관리

디자인 규칙·수치·기존 결정·이력의 기준은 이 저장소입니다. 참고 안내의 Base UI·Nova·neutral 또는 프론트 토큰 예시를 이유로 기존 Figma 변수·컬러·타이포를 교체하지 않습니다. 개발과의 차이는 기존 [역할 분담](docs/ai-collaboration.md)에 따라 기록하고 협의합니다.

- [업무 시작점](workflows/AGENTS.md)에서 검토·수정·개발 전달·작업 재개에 필요한 자료와 절차를 선택합니다. 기존 작업 A/B/C의 수행·검수 기준은 유지합니다.
- [프로젝트 공통 지침](https://idtloungepmo.github.io/lounge3.0_guide/AGENTS.md)을 함께 확인하고 접근 여부를 구분합니다.
- 문서만 편집하는 작업은 [문서 지침](docs/AGENTS.md)에 따라 확인합니다. 이 경우 Figma 컬러 대조·폰트 로드·화면 검수는 문서 수정의 필수 선행 작업으로 요구하지 않습니다. Figma 디자인 작업에는 기존 규칙을 적용합니다.
- 사람용 안내는 [index.html](index.html), 내용 원본은 [index.md](index.md)입니다. 안내를 바꾸면 둘을 맞추고 상세 기준은 원본 문서로 연결합니다.
- 작은 수정의 기록은 [작업 기록 안내](tasks/README.md)의 최소 항목을 사용합니다. 기존의 종료 이력 기록 원칙은 유지하며, 단순 검토 의견은 답변에 남길 수 있습니다.
- 스킬은 [선택·연결 안내](workflows/skills/AGENTS.md)에 따라 필요한 것만 사용합니다. 문서의 예시 명령을 실제 설치·실행으로 간주하지 않습니다.
