# 디자인팀 AI 공통 규칙

## 1. 목적과 작업 범위

AI는 다음 세 가지 작업을 수행한다.

1. Shadcn UI 기반 디자인 시스템을 확정 메인시안에 맞게 수정한다.
2. 수정된 디자인 시스템과 화면설계서를 사용하여 서브페이지를 디자인한다.
3. 고객 요청에 따른 수정사항을 반영한다.

작업 순서: Shadcn UI 기반 구축 → 메인시안 반영 → 서브페이지 제작 → 사용 여부 확인 → 미사용 컴포넌트 정리. 고객 수정은 각 단계에서 발생할 수 있다.

## 2. 현재 합의된 공통 규칙

- Shadcn UI를 디자인 시스템의 기반으로 사용한다.
- 기존 변수 구조와 의미를 유지하며 그 구조에 맞춰 컴포넌트를 수정한다.
- 메인시안에 따라 변수 값을 변경할 수 있다. 변경은 요청된 범위와 영향 검토를 따른다.
- 변수의 컬렉션·그룹·이름·모드·타입·별칭 참조 관계를 임의로 변경하거나 삭제하지 않는다. 실제 구조는 기준 파일을 확인한다.
- 색상이 비슷하다는 이유만으로 서로 다른 역할의 변수를 통합하지 않는다.
- 기존에 변수로 관리되는 속성의 연결을 임의로 끊지 않는다. 기존 변수에 없는 속성까지 억지로 연결하지 않는다.
- 기존 구조로 표현할 수 없는 요구는 예외 또는 확장 제안으로 기록하고 검토받는다.
- 컴포넌트는 한 페이지에서 기존 이름을 기준으로 알파벳순으로 정리한다. 이 순서는 탐색용이며 수정 순서를 강제하지 않는다.
- 현재 단계에서 사용 여부를 이유로 컴포넌트를 임의로 삭제하지 않는다. 추후 실제 사용 범위가 확인되면 정리한다.
- 컴포넌트 정리와 변수 정리를 분리한다. 컴포넌트 삭제를 이유로 공유 변수를 함께 삭제하지 않는다.
- 원본 컴포넌트와 인스턴스 관계, 기존 속성 및 상태를 유지한다. 변경이 필요하면 영향을 기록한다.
- 메인시안에 없는 정책·상태·반응형 규칙은 확정 사실로 만들지 않는다.

## 3. 문구와 누락 정보

- 화면설계서의 제목·본문·버튼·탭·플레이스홀더·예시값·날짜·마스킹·타이머 문구를 원문 그대로 사용한다. 보기 좋게 다듬거나 서비스명을 임의 교정하지 않는다.
- 오탈자, 정책과 표시값의 충돌은 결과 화면 밖의 작업 기록에 원문·위치·질문을 남긴다. 사용자가 명시적으로 승인한 변경만 해당 범위에 적용한다.
- 다른 화면의 문구나 입력 항목을 근거 없이 가져오지 않는다. 설계서 누락은 표시하고, 공통 화면 재사용은 근거와 대상 범위를 제시해 확인받는다. 기존 승인 범위는 다시 승인받지 않는다.
- 기능·상태·입력 항목·동의 항목의 의미를 유지한다. 설명 문구를 체크박스나 버튼으로 바꾸지 않는다.

## 4. 글꼴과 변수 연결

- 작업 전에 AI 연결 환경에서 Pretendard와 필요한 굵기를 실제로 로드한다. 사용자 PC에서 표시된다는 사실만으로 사용 가능하다고 판단하지 않는다.
- 불러올 수 없으면 영향받는 작업을 보류하고 이유를 보고한다. 대체 글꼴을 임의로 적용하거나 완료로 보고하지 않는다. 독립적으로 진행 가능한 작업은 계속한다.
- 새 제목·본문·안내·라벨도 기존 Family·Weight·Size 및 해당하는 Line height·Letter spacing·Color 변수를 연결한다. 이미 사용 가능한 변수가 있는 속성을 직접 지정한 값으로 끝내지 않는다.
- 변수의 숫자 값과 화면에 적용된 실제 글꼴·굵기를 함께 검증한다. 혼합 스타일 텍스트는 구간별로 확인한다.
- 기존 인스턴스의 변수 연결을 유지한다. 동일 목적의 변수를 중복 생성하지 않는다.

## 5. 편집 범위와 완료 기준

- 시작 전에 소스 페이지·결과 페이지·허용 노드·보호 대상을 구분한다. [현재 Figma 위치](docs/design-system.md#현재-figma-위치)를 확인한다.
- 화면설계서·참고 시안·검토 전용 페이지는 읽기 전용으로 취급한다. 수정은 별도 명시된 요청에 한한다.
- 변경에 필요한 부분만 수정한다. 단순 문구·폰트 변경 때문에 프레임 전체나 무관한 요소를 재생성하지 않는다.
- [공통 검수표](docs/quality-checklist.md)를 필수로 적용한다. 미검수·불일치·임시 적용이 남으면 전체 완료로 표시하지 않는다.
- 결과는 완료·미완료·임시 적용으로 구분하고, 링크와 노드 ID·예외 사유·검수 범위를 기록한다.

## 6. 모든 작업에 적용할 실행 절차

1. 작업 요청과 관련 기준 자료의 버전을 읽는다.
2. 실제 대상, 변수 연결, 컴포넌트 관계를 확인한다.
3. 수정 범위와 다른 화면에 미칠 영향을 정리한다.
4. 허용 범위 안에서 작업한다. 공통 변수 변경은 공유된 영향 범위까지 확인한다.
5. 해당 작업의 검수표에 따라 확인하고 문제를 수정한다.
6. 결과 링크, 변경 내용, 검수 결과, 미확정 사항을 제출한다.

기준이 충돌하면 먼저 확정 여부·버전·적용 범위를 비교한다. 해결되지 않으면 영향받는 부분을 임의로 결정하지 않고 질문한다. 영향 없는 작업은 계속할 수 있다.

운영 제안: 초안 위치에서 대표 컴포넌트와 대표 화면을 검토한 뒤 나머지로 확장한다. 초안 위치로 복제할 때도 기존 변수와 컴포넌트 참조가 유지되는지 확인한다. 이 운영 방식은 담당자가 확정한다.


## 기준 자료와 기록

- 실제 기준: [디자인 시스템](docs/design-system.md), [컴포넌트 목차](docs/components.md).
- 작업별 절차: [Shadcn 수정](workflows/01-shadcn-update.md), [서브페이지](workflows/02-subpage-design.md), [고객 수정](workflows/03-client-revision.md).
- 요청과 결과: [작업 양식](tasks/TEMPLATE.md).
- 미입력 값과 확인 불가 항목을 확정 사실로 취급하지 않는다.
- 원본 파일과 변수 구조를 확인하지 않고 검사 완료 또는 수정 완료로 보고하지 않는다.
- 작업 범위 밖의 파일과 Figma 노드를 임의로 변경하지 않는다.

## 폴드폰 대응

[폴드폰 대응 기준](docs/foldable.md)을 적용한다. 확장 배치는 마이페이지 메인·사용처 보기·제휴카드에 한정하고 동일 데이터·기능으로 배치만 변경한다. 접으면 현재 APP 레이아웃에서 보고 있던 콘텐츠를 이어서 표시한다. 접기·펼치기 양방향으로 콘텐츠·선택·읽던 위치·입력 상태를 유지한다. 나머지 페이지는 기존 반응형 기준을 적용한다. 미확정 전환 너비나 동작은 임의로 확정하지 않는다.
