# 디자인팀 AI 공통 규칙

## 1. 목적과 작업 범위

AI는 다음 세 가지 작업을 수행한다.

1. Shadcn UI 기반 디자인 시스템을 확정 메인시안에 맞게 수정한다.
2. 수정된 디자인 시스템과 화면설계서를 사용하여 서브페이지를 디자인한다.
3. 고객 요청에 따른 수정사항을 반영한다.

작업 순서: Shadcn UI 기반 구축 → 메인시안 반영 → 서브페이지 제작 → 사용 여부 확인 → 미사용 컴포넌트 정리. 고객 수정은 각 단계에서 발생할 수 있다.

## 2. 현재 합의된 공통 규칙

- Shadcn UI를 디자인 시스템의 기반으로 사용한다.
- 기존 변수 구조와 의미를 유지하며 그 구조에 맞춰 컴포넌트를 수정한다.
- 메인시안에 따라 변수 값을 변경할 수 있다. 변경은 요청된 범위와 영향 검토를 따른다.
- 변수의 컬렉션·그룹·이름·모드·타입·별칭 참조 관계를 임의로 변경하거나 삭제하지 않는다. 실제 구조는 기준 파일을 확인한다.
- 색상이 비슷하다는 이유만으로 서로 다른 역할의 변수를 통합하지 않는다.
- 기존에 변수로 관리되는 속성의 연결을 임의로 끊지 않는다. 기존 변수에 없는 속성까지 억지로 연결하지 않는다.
- 기존 구조로 표현할 수 없는 요구는 예외 또는 확장 제안으로 기록하고 검토받는다.
- 컴포넌트는 한 페이지에서 기존 이름을 기준으로 알파벳순으로 정리한다. 이 순서는 탐색용이며 수정 순서를 강제하지 않는다.
- 현재 단계에서 사용 여부를 이유로 컴포넌트를 임의로 삭제하지 않는다. 추후 실제 사용 범위가 확인되면 정리한다.
- 컴포넌트 정리와 변수 정리를 분리한다. 컴포넌트 삭제를 이유로 공유 변수를 함께 삭제하지 않는다.
- 원본 컴포넌트와 인스턴스 관계, 기존 속성 및 상태를 유지한다. 변경이 필요하면 영향을 기록한다.
- 메인시안에 없는 정책·상태·반응형 규칙은 확정 사실로 만들지 않는다.

## 6. 모든 작업에 적용할 실행 절차

1. 작업 요청과 관련 기준 자료의 버전을 읽는다.
2. 실제 대상, 변수 연결, 컴포넌트 관계를 확인한다.
3. 수정 범위와 다른 화면에 미칠 영향을 정리한다.
4. 허용 범위 안에서 작업한다. 공통 변수 변경은 공유된 영향 범위까지 확인한다.
5. 해당 작업의 검수표에 따라 확인하고 문제를 수정한다.
6. 결과 링크, 변경 내용, 검수 결과, 미확정 사항을 제출한다.

기준이 충돌하면 먼저 확정 여부·버전·적용 범위를 비교한다. 해결되지 않으면 영향받는 부분을 임의로 결정하지 않고 질문한다. 영향 없는 작업은 계속할 수 있다.

운영 제안: 초안 위치에서 대표 컴포넌트와 대표 화면을 검토한 뒤 나머지로 확장한다. 초안 위치로 복제할 때도 기존 변수와 컴포넌트 참조가 유지되는지 확인한다. 이 운영 방식은 담당자가 확정한다.
